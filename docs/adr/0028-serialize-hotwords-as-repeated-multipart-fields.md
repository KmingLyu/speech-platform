# Serialize Hotwords as repeated multipart fields

The public `hotwords` contract remains an array of independent Hotwords, and its multipart OpenAPI encoding uses `style=form` with `explode=true` so Swagger UI emits one field per item. We do not interpret commas as separators: a comma inside one Hotword is literal, which preserves the distinction between repeated values and a single phrase containing punctuation while matching the worker's existing conversion to faster-whisper's single hint string.

## Consequences

- Swagger-generated requests contain repeated `hotwords` fields and are accepted without changing the API's validation or persistence model.
- Requests generated by older Swagger schemas that contain one comma-separated field are treated as one Hotword and must be regenerated or edited manually.
