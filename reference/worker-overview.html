Worker 大觀念速查

一句話：API 負責登記工作，PostgreSQL 像工作清單，Worker 負責認領並執行。

工作流

  1. Client 向 API 提交來源。
  2. API 建立一筆 queued job，立即回應，不等待辨識完成。
  3. Worker 從資料庫安全認領一筆尚未處理的 job。
  4. Worker 下載或讀取來源、轉換媒體、執行 ASR、產生 artifacts。
  5. Worker 更新狀態；Client 之後查詢或下載結果。

多 Worker

原則上可行。資料庫的鎖定機制避免多個 Worker 認領同一筆工作，因此可以水平增加處理者。

但吞吐量不會無限增加：每個 Worker 都可能需要一份模型與 GPU 記憶體；共同的 GPU、CPU、磁碟、資料庫和共享檔案空間都可能成為瓶頸。

因此「能同時啟動」和「值得同時啟動」是兩件事。部署前要確認 GPU 記憶體、GPU 計算能力、I/O、資料庫，以及失聯 Worker 的恢復機制。
